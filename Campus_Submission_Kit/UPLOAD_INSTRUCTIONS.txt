SUBMISSION KIT — WHAT TO DO

Copy the following files into the ROOT of your existing GitHub repository (retaining folders):
  README.md
  .github/workflows/tests.yml
  docs/BACKLOG.md
  docs/EVIDENCE_INDEX.md
  docs/REVIEW_REQUEST.md
  run_tests_windows.ps1

Use git add/commit/push or GitHub's Add file > Upload files. These are prepared files, NOT uploaded to GitHub automatically.

Once pushed, navigate to GitHub > Actions > B1 Validation Tests and inspect the run. Report its ACTUAL result. A red run indicates a failure to resolve, not evidence of success.

To run locally (PowerShell, at project root):
  powershell -ExecutionPolicy Bypass -File .\run_tests_windows.ps1

The script generates dated files under evidence/. Review them, then upload appropriate test evidence without personal/secrets data. A successful CI workflow should have a linked run URL in docs/EVIDENCE_INDEX.md.

For final submission SHA, run:
  git rev-parse HEAD
Paste the full SHA into the report, README and evidence index after final changes.

Ask a fellow team member to independently review and record an authentic GitHub comment. If reviewing already-merged PR #2, call it a retrospective review and do not describe it as a pre-merge approval.

Do not check off tasks or claim tests/review have passed unless the evidence really exists.
